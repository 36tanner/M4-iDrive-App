# F82 M4 / S55 build

This branch adds a read-only M4 variant of BoostDeck and ShiftDeck for a 2016 F82 M4 (S55, M DCT) with an
NBT Evo retrofit on `NBTevo_N18092I`. Nothing in it writes to an ECU. It builds with `M4=1`; without that flag every
app builds exactly as upstream.

**Status:** the source and host tests are complete, and the S55 signals were read from the car itself
(below). The ARM build and the in-car check of the new screens have not been done yet. See
[Before trusting it](#before-trusting-it).

## This car's capture (2026-11-23)

The installer's compatibility check passed: `NBTevo_N18092I`, 1280 × 480, frameworks matched. The
diagnostic gateway is **169.254.61.31**, not the default 169.254.21.3, so the package needs
`--gateway 169.254.61.31`. `probe_signals.py` replies, read only:

| Request | Engine off | Idle | Decoded (off → idle) |
| --- | --- | --- | --- |
| `22 4408` oil temp | `00DA` | `00EB` | 21.8 → 23.5 °C |
| `22 4300` coolant (1 byte) | `5C` | `6B` | 21.0 → 32.3 °C |
| `01 23` rail pressure | `0046` | `07C8` | 7.0 → 199.2 bar (cold-start pressure) |
| `22 56D7` | NRC 31 | NRC 31 | refused, as OBDb showed |
| `22 4AB0` boost target | `64A0` | `64A0` | 100.6 kPa absolute (no boost) |
| `22 402B` battery | `...708C...` | `...7E2C...` | 13.2 → 14.1 V |
| `22 4A2E` rev limit | `0FE7` | `17EA` | 4071 → 6122 rpm (variable redline) |
| `22 4201` / `4205` | `64A1` / `3252` | `64A1` / `3243` | baro 100.6 kPa, boost about 0 |
| `22 5889` lambda | `FFEB` | `0FDA` | unavailable → λ 0.991 (AFR 14.6) |
| `22 586F` oil pressure | `0406` | `0D19` | 1.03 → 3.35 bar absolute, so 0 → 2.35 bar gauge |
| EGS `22 DA12` | NRC 31 | | the DCT has no transmission temperature here |

Tires (DSC) are outside what `probe_signals.py` can ask for, so they're still unverified.

## What changes

### BoostDeck

| Tile | Upstream (B58 340i) | M4 build | Source |
| --- | --- | --- | --- |
| Boost | DME `4205` − `4201` | same | OBDb 2015 M4 recorded |
| AFR | DME `5889` | same | OBDb 2015 M4 recorded |
| Timing | DME `4A49` (cyl 1) | same | OBDb 2015 M4 recorded |
| Intake air | DME `580F` | same | OBDb 2015 M4 recorded |
| Transmission → **Oil temp** | EGS `DA12` (ZF 8HP) | DME `4408`, 2 bytes ÷ 10 °C | OBDb 2015 M4 recorded |
| Rail pressure | DME `56D7` | **OBD PID `01 23`**, 10 kPa per count | 2015 M4 *refuses* `56D7` (OBDb); PID 23 is SAE J1979 and listed as supported |
| Oil pressure | DME `586F` | DME `586F` **minus ambient**: the S55 reports absolute pressure | this car: 1.03 bar engine off, 3.35 bar at idle |
| Coolant | DME `4300`, 2 bytes | DME `4300`, **1 byte** × 0.75 − 48 °C on pre-2019 DMEs (both forms decode) | OBDb 2015 M4 recorded |
| Active E → **Engine** (warm-up) | MHD MG1 ethanol query | oil and coolant temperature → COLD / WARM / GO / HOT | thresholds below |

The ethanol query (`2C 88 01`) was written for MHD on the B58's MG1 DME. The S55 uses a different
Bosch family, so the M4 build never sends it.

**Gauge colors.** A bar keeps your chosen color until a reading crosses a limit. It turns yellow for
caution and red for warning. iDrive draws the label text itself, so the text stays white.

| Gauge | Yellow | Red | Note |
| --- | --- | --- | --- |
| Boost | ≥ 3 psi under target | ≥ 5 psi under target | only after ≥ 1 s below target, so normal spool-up doesn't flash it |
| AFR | > 13.0 | > 13.5 | only at ≥ 8 psi of boost |
| Intake air | ≥ 50 °C | ≥ 65 °C | |
| Oil temp | ≥ 120 °C | ≥ 135 °C | |
| Coolant | ≥ 110 °C | ≥ 115 °C | |
| Timing, rail pressure, oil pressure | — | — | left uncolored: I don't have trustworthy S55 limits for these |

**Engine column (warm-up).** The bar fills as oil goes from 20 °C to 75 °C. It shows COLD (blue) below 40 °C,
WARM (yellow) until oil reaches 75 °C and coolant 75 °C, then GO (green), and HOT (red) at the oil or coolant
red limit. All limits are constants at the top of `native/src/m4_signals.c`.

**OPTIONS → Details** shows:

- Health line: `OK`, or `Check:` followed by a list (battery low, a tire below its set point by 0.2 bar,
  oil or coolant hot, boost under target, lean under boost).
- Warm-up status with oil and coolant.
- Boost vs the DME's boost target (`4AB0`, absolute kPa ÷ 256, converted to gauge pressure).
- Battery voltage (`402B`) and the DME's current rev limit (`4A2E`). That's the variable-redline value,
  and it rises as the engine warms.
- Tire pressures, set points and temperatures, read from the DSC (`DC98`–`DC9B`).
- Peaks since the last reset: boost, intake air, oil, coolant, plus the lowest timing and leanest AFR
  while under boost.
- Buttons: **Reset peaks**, **Logging on**, **Logging off**.

Units follow the existing Imperial/Metric option. Tire pressures show in psi when Imperial is selected.

**Logging.** **Logging on** creates `BoostDeck/logging-enabled`. While BoostDeck or its Details screen is
open, the collector writes CSV rows at 10 Hz to `/var/opt/hmi/data/ID5/Plugins/BoostDeck/logs/log-0.csv`
through `log-3.csv`. Each file is capped at 2 MB, the oldest file is reused, and logging pauses if the volume has
less than 20 MB free. Columns:

```
t_s,boost_psi,afr,timing_deg,intake_c,oil_c,rail_bar,oil_bar,coolant_c,boost_target_psi,battery_v,rev_limit_rpm
```

Copy them off with temporary SSH enabled:

```bash
scp -O 'root@HEAD_IP:/var/opt/hmi/data/ID5/Plugins/BoostDeck/logs/*.csv' .
```

### ShiftDeck

**OPTIONS → Performance timers** shows 0–60 mph, 0–100 km/h, 60–130 mph, 100–200 km/h, and the quarter mile with
trap speed, each with the last and best result, plus a **Reset timers** button.

- Stop for half a second to arm the standing timers. They start at the last zero-speed sample, which is
  slightly conservative.
- Rolling timers start when you cross the lower speed. They abort if speed falls 5 km/h below the run's peak.
- Crossings are interpolated between samples. Speed is OBD `01 0D` (whole km/h) at about 15 Hz, so results
  are estimates, typically within about 0.1 s.
- The worker keeps running while ShiftDeck or its timers screen is open. Results reset when iDrive restarts.

## Laptop logger (no build needed)

`tools/log_signals.py` logs the S55 signals to CSV from a laptop on wired ENET, using the same read-only
requests: about 7 rows a second with RPM, speed, boost and target, AFR, rail pressure, timing for cylinders
1–4, plus intake, oil, coolant and oil pressure once a second.

```bash
py tools/log_signals.py --local LAPTOP_169.254_IP --gateway 169.254.61.31
```

Ctrl+C stops it. The CSV lands in the current folder as `m4-log-<date-time>.csv`.

## Build

You need the toolchain and framework copies described in [BUILD.md](BUILD.md). Then:

```bash
make -C native test
```

```bash
M4=1 sh native/build.sh
```

```bash
python3 native/tools/m4_package.py --dashboard ../packages/dashboard.zip --native native/out --gateway 169.254.61.31 --out m4-dashboard.zip
```

`--resources-only` (instead of `--native`) builds a review copy with only the new screens. That copy still
has the stock native files and must not be installed.

## Install

Follow [AgentReadMe.md](../../AgentReadMe.md#stage-and-verify): check the firmware and framework hashes,
move the existing `BoostDeck` and `ShiftDeck` folders to a backup outside `Plugins`, upload the folders from
the M4 ZIP, make the `-qnx` workers executable, compare checksums against `SHA256SUMS`, then restart iDrive
while parked. Uninstalling or restoring works the same way as upstream.

## Before trusting it

1. **Parked, ignition on, engine off:** open BoostDeck. Coolant, oil temp and intake air should match MHD
   or the cluster. Boost should read about 0.
2. **Parked, engine idling:** rail pressure should read about 50 bar, oil pressure about 1–2 bar, AFR about
   14.7. Details should show battery about 14 V and tire pressures that match the iDrive tire screen.
3. If a tile shows `--`, run the collector by hand with `--trace` over SSH and record the raw replies:

```bash
/var/opt/hmi/data/ID5/Plugins/BoostDeck/boostdeck-collector-qnx --host 169.254.21.3 --cycles 40 --trace
```

4. Only then use the colors and timers. Do a timed run on a closed road or a track.

**Not verified yet:** the ARM build itself (QNX 6.5 toolchain), the RHMI screens on the head unit (the Details
and Timers screens follow the existing list-screen pattern, but are untested), and tire reads through the
gateway. The DSC can't be reached over the MOST fallback, so tires stay
blank there.
